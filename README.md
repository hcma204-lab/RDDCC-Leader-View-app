# 研發文管課｜主管儀表板

單一 `index.html`，沒有後端、沒有建置步驟、不依賴任何外部 CDN。
monday 看板當資料庫（唯讀），逾期／靜默／審核積壓／負載全部在瀏覽器本機計算；AI 功能選填，接你們自己的 LLM 端點。

## 它做什麼

| 區塊 | 說明 | 是否用 AI |
|---|---|---|
| 今天最該先處理 / KPI | 逾期、等你審核、7 天內到期、靜默風險、待拍板 | 否（本機計算） |
| 需要你決策 | 依緊急度排序：審核積壓、暫緩逾期、該啟案未啟案、嚴重逾期、靜默、即將到期無更新 | 否 |
| 各人負載／逾期分級 | 進行中＋審核中；偏高門檻、全部卡審核會標示 | 否 |
| 表格 | 等你審核／靜默風險／即將到期／全部進行中，可搜尋 | 否 |
| AI 助理 → 晨報 | 本機晨報一律可用；按鈕可請 AI 改寫成口語版 | 選填 |
| AI 助理 → 預審 | 讀取單一送審項目，本機檢查完整度（內容、檔案、子項目、需求確認、完成日、留言）；按鈕可請 AI 給核准／退回建議 | 選填 |
| AI 助理 → 催辦草稿 | 依負責人彙整需催辦項目，產生訊息草稿（**不會自動寄出**） | 選填 |
| AI 助理 → 問答 | 對目前進行中項目提問 | 選填 |

## 視覺化功能（為「主管日常掌握」與「向總經理報告」設計）

頁面上方有四個分頁：**儀表板｜視覺總覽｜週會週報｜總經理視角**（網址後加 `#viz`、`#weekly`、`#gm` 可直接開啟）。

| 位置 | 內容 | 給誰、解決什麼 |
|---|---|---|
| 儀表板：**團隊健康燈號** | 每位同仁一格：● 需關注／◐ 留意／○ 正常，附進行、逾期、靜默、等審數量；點名字直接看他的週報 | 主管：3 秒知道誰有狀況。只看「他自己能掌控的事」，項目卡在等主管審核不算他的錯，會標「全部在等你審核」 |
| 儀表板：**KPI 迷你趨勢線** | 逾期、等審核、7 天內到期、靜默、待拍板各附一條近 30 天趨勢線 | 主管：看到是在變好還是變差。每天開頁面累積一筆，只存在這台瀏覽器 |
| 視覺總覽：**團隊狀態矩陣** | 人 × 指標的熱圖，顏色越深數量越多 | 主管：哪位同仁、哪一項偏高 |
| 視覺總覽：**時程甘特圖** | 每個案子一條時程；深色段＝時間已過的比例；**紅色斜線＝已逾期多久**；可依負責人篩選、選看未來 3／6／12 個月 | 主管、總經理：整體排程與拖延的樣子 |
| 視覺總覽：**每週新增 vs 完成** | 近 10 週柱狀圖，並自動寫出一句結論（例如「新增 15 項、完成 0 項，產出停擺，同時有 17 項等待審核」） | 主管：產出是否被審核卡住 |
| 視覺總覽：**工作分佈** | 依類型、依系統別 | 總經理：團隊的力氣花在哪 |
| 視覺總覽：**等你審核的時間** | 每個等審項目的等待天數長條 | 主管：審核積壓有多久 |
| **總經理視角** | 整體燈號＋計畫性專案一覽（風險、時間進度條、最新進度）、需要總經理知道的風險與建議處置、產出趨勢、近 14 天完成、團隊負載。可**複製摘要**、**列印**、**AI 撰寫摘要** | 總經理：不看細節就能掌握，也是主管向上報告的素材 |

**燈號怎麼判斷**（全部可在 `CONFIG` 調整）：
- 個人燈號：有嚴重逾期、或逾期達 3 項、或靜默高風險達 2 項 → 紅；有任何逾期、靜默、暫緩逾期或負載偏高 → 黃；否則綠。
- 專案風險：暫緩且已逾期、嚴重逾期（超過 30 天）、長期無動靜 → 需關注；一般逾期、久未更新、暫緩中、該啟案未啟案 → 留意。
- 總經理視角的整體燈號：需關注的專案達 2 項或占 25% 以上 → 紅；有 1 項需關注或留意占 30% 以上 → 黃。
- **時間進度不是工作完成度**：只代表今天落在預計時程的哪個位置。看板沒有工作完成百分比，所以不會假裝有。

## 週會週報（頁面上方「週會週報」分頁，網址後加 `#weekly` 可直接開啟）

**設計重點：所有進行中的案子，每週都會列出來，不論負責人有沒有更新。**
monday 現有的「本週進度更新」檢視是「有更新才出現」，所以執行中卻沒人更新的案子反而看不到。這個分頁反過來做：

- 依**負責人**分組，每個案子顯示狀態、到期／逾期、預計時程，以及負責人填在「**重點事項**」欄位的內容。
- 用**重點事項欄位的最後修改時間**判斷「近 7 天（或 14 天）有沒有更新」：有更新標 ✔，沒更新或空白標 ⚠，會議上就知道要追問誰。
- 每位負責人另列：**暫緩／未啟案**（需決議是否續做）、**近期完成**。
- **逐人報告模式**：一次只顯示一位，字體放大，按「上一位／下一位」或鍵盤 ← → 切換。
- 每個案子有「**已報告**」勾選與「**會議備註／決議**」欄，開會時直接記。這些只存在這台瀏覽器（依週分開），**不會寫回 monday**。
- **複製週報**（純文字，含會議備註，可貼 Teams／Email）、**列印**（自動隱藏按鈕與備註空欄）、**AI 摘要**（選填，把全部重點事項整理成給主管的週會摘要）。

預設不含「例行性」項目，可用「含例行性」勾選。

## 第一次使用

1. 直接用瀏覽器開 `index.html`（雙擊即可），按「看示範資料」先看畫面（假資料）。
2. 「設定」→ 貼上 monday API token → 「測試 monday 連線」→ 「儲存並載入」。
   token 取得：monday 右上頭像 → Developers → My access tokens。
3. 想要自動提醒與 AI 晨報：見下一節「主動提醒與 AI」。不設定也能用所有本機功能。

## 主動提醒與 AI（用公司 Claude 帳號，不需 API key、不扣 monday 點數）

**設計**：Claude 桌面 App 的「排程任務」會自動執行，用你登入的公司 Claude 帳號（用量算在企業帳號）。分工如下：

- `brief-cli.js` 負責**算**：讀 monday、用和儀表板同一套引擎分析，所以數字一定和儀表板一致。
- **Claude 排程任務**負責**判讀與寫作**：把分析結果寫成晨報、預警、週會摘要、給總經理的摘要。
- 結果會 ① 存回 monday「🤖 主管晨報與預警」看板、② 跳出 **Windows 通知**、③ **自動顯示在儀表板**上（打開頁面就看到，不用按任何按鈕）。

| 排程任務 | 時間 | 內容 |
|---|---|---|
| 每日主管晨報（`cf-daily-brief`） | 平日 08:30 | 需決策、到期、逾期與靜默、團隊狀況、產出趨勢；Windows 通知 |
| 到期預警（`cf-due-alert`） | 平日 15:30 | 今天到期、3 天內到期卻沒更新、剛逾期；**沒有新的預警就不發，也不重複預警同一項** |
| 每週摘要（`cf-weekly-briefing`） | 週一 08:45 | 靜默風險週報、週會摘要、給總經理的摘要 |

（實際時間會有幾分鐘的錯開，這是排程功能用來分散負載的設計。）

### 一次性設定（約 2 分鐘）

1. 雙擊 `setup-monday-token.bat`，貼上你的 monday API token（輸入時不顯示）。token 只存在你的使用者資料夾（`~/.cfdash-monday-token`），不在專案資料夾，也不要提交到 GitHub。
2. 在 Claude 桌面 App 左側「排程」區，確認三個任務都在。
3. 對 `cf-daily-brief` 按一次「**立即執行**」測試：應該會跳出 Windows 通知，並在 monday 輸出看板與儀表板出現晨報。

### 使用上要知道

- **Claude 桌面 App 要開著**（可以縮小）才會按時執行；App 關著時，下次開啟會補跑。電腦睡眠或關機期間不會執行。
- 任務以「自動模式」儲存，執行時不會停下來問你；若想改，在 App 的排程區編輯該任務。
- 任務失敗（例如 token 過期、連不到 monday）時，程式會自己跳出 Windows 通知告訴你，不會默默失敗。
- 儀表板上的 AI 面板如果顯示「已 N 天沒有新內容」，代表排程沒在跑，請確認 App 是否開著。
- 排程時間可以在 App 的排程區修改；提示詞（晨報格式、規則）也在那裡，可以直接改。
- 預警會記住近 3 天已通知過的項目（存在 `~/.cfdash-alert-state.json`），避免同一件事天天吵你。

### 進階（選填）：儀表板上的即時 AI 按鈕

儀表板的「AI 摘要」、預審、催辦改寫、問答按鈕，需要另外啟動本機橋接程式才能用：

1. 雙擊 `login-claude.bat`，輸入公司 Email，用公司 Claude 企業版帳號（SSO）登入一次。
2. 每次使用前雙擊 `start-claude-bridge.bat`，視窗會顯示連線碼，保持視窗開著。
3. 儀表板「設定」→ AI 類型選「Claude Code」→ 貼上連線碼 → 「測試 AI 連線」。

**不使用這些按鈕，完全不影響上面的自動排程與面板。** 橋接程式只接受本機（127.0.0.1）連線、每個請求都要帶連線碼、執行時關閉所有工具、不留對話紀錄、不記錄內容；不讀取、不轉存你的登入憑證。

## 給其他主管使用（各人用自己的 monday token，約 3 到 5 位）

連結給他們，他們第一次打開會看到圖文引導，照著做即可：

1. monday 右上角**頭像 → Developers → My access tokens → Show**，複製。
2. 儀表板「開啟設定」→ 貼上 → 「測試 monday 連線」→ 「儲存並載入」。
3. 之後每次打開都是最新資料，不用再貼。

要知道的事：

- **前提**：他們的 monday 帳號要能使用 Developers 功能。找不到的話，引導畫面有「複製給管理員的說明」按鈕，貼給 monday 管理員，請管理員**讓這幾位主管保留**這個功能。
- 他們只看得到**自己有權限**的看板。「研發文管課」是封閉型工作區，要是工作區成員才看得到。
- **權限範圍**：個人 token 等同本人帳號權限（可讀、可改），所以務必只存在自己的瀏覽器、不要給別人。共用電腦請用完按右上角「登出」。
- 管理員可以在「管理員 → 連結 → 管理 API token」看到並撤銷任何人的 token。被撤銷時，儀表板會顯示「monday 拒絕了這組 token」，重新貼新的即可。
- **AI 面板**：「AI 晨報」等面板讀的是你的私人輸出看板「🤖 主管晨報與預警」。要讓其他主管也看得到，請在 monday 把該看板分享給他們（檢視權限即可），否則他們的畫面會顯示「還沒有內容」，其他功能不受影響。排程產生與 Windows 通知只在你的電腦上跑。
- 如果人數增加（十位以上），建議改用「monday 帳號登入」（OAuth），需要 IT 與管理員配合；目前 3 到 5 位用個人 token 即可。

## 安全須知（重要）

- **token 與 API key 不要寫進程式碼，也不要提交到 GitHub。** 頁面只把它們存在使用者自己瀏覽器的 localStorage（設定裡可取消「記住」，共用電腦請取消）。
- 儲存庫裡不含任何公司資料：資料是開啟頁面時用使用者自己的 token 即時向 monday 讀取。看得到什麼，取決於該 token 的 monday 權限。
- 本頁**只讀** monday，不會寫入、不會改狀態、不會通知任何人。
- AI 排程任務會把彙整後的項目名稱、負責人、日期、狀態（週會與總經理摘要還含重點事項文字）交給你登入的公司 Claude 帳號處理，產出存回 monday 輸出看板。儀表板上的即時 AI 按鈕（選填）同樣是交給你的公司 Claude 帳號，或你填的 API 端點。請只用公司核准的方式。
- `claude-bridge.js` 的連線碼存在你的使用者資料夾（`~/.cfdash-bridge-token`），不在本資料夾，也不要提交到 GitHub。
- 瀏覽器直連 LLM 時，端點必須允許跨來源（CORS）：
  - Azure OpenAI：在資源的 CORS 設定加入你的 Pages 網址。
  - Ollama：啟動時設 `OLLAMA_ORIGINS`。
  - Anthropic：已自動帶上瀏覽器直連所需的標頭。
  - 若公司端點不允許 CORS，需要另外架一個小代理（可以之後再做）。

## 怎麼改

所有可調整的東西都在 `index.html` 裡 `1. CONFIG` 那一區（搜尋 `CONFIG = {`）。

| 想改什麼 | 改哪裡 |
|---|---|
| 看板 ID | `CONFIG.monday.boardId`（或設定視窗） |
| 欄位對應（換看板、欄位改名） | `CONFIG.columns`，值是 monday 欄位 ID |
| 狀態標籤文字 | `CONFIG.statusLabels`（要和 monday 上完全一致）；`statusFilterIndexes` 是這些狀態在 monday 的 index |
| 排除的群組（例行性／結案／作廢） | `CONFIG.excludeGroupIds` |
| 逾期、靜默、負載等門檻天數 | `CONFIG.rules`（`overdueSevere`、`staleDays`、`loadWarn`…） |
| 哪些項目不納入靜默判斷 | `CONFIG.rules.ignoreNameRegex`（正規表示式） |
| 週報預設回顧幾天、可選哪些天數 | `CONFIG.weekly.windowDays`、`windowChoices` |
| 週報的負責人報告順序 | `CONFIG.weekly.ownerOrder`（填名字片段，例如 `['施俞安','黃宜靖']`） |
| 週報預設是否含例行性 | `CONFIG.weekly.includeRoutine` |
| 週報判斷「有更新」用哪個欄位 | `CONFIG.columns.keyPoints`（重點事項欄位 ID） |
| 健康燈號變紅的門檻 | `CONFIG.health` |
| 總經理視角納入哪些專案 | `CONFIG.gm.groupIds`（群組 ID，預設「計畫性」）、`CONFIG.gm.types`（類型，預設「季目標」） |
| 甘特圖往前看幾天／可選的未來範圍 | `CONFIG.viz.ganttPastDays`、`ganttFutureChoices` |
| 趨勢圖顯示幾週 | `CONFIG.viz.flowWeeks` |
| 新增／完成趨勢最多抓多少筆已完成項目 | `CONFIG.weekly.doneFetchLimit` |
| 主管本人名稱 | `CONFIG.managerName` |
| 「需要你決策」有哪些類別、怎麼排序 | `analyze()` 內「需要你決策」那一段（每一類是一行 `push(...)`） |
| AI 的口吻與限制 | `SYS`（系統提示）與各按鈕的提示詞 |
| 版面與顏色 | 檔案最上方的 `<style>`，顏色都是 `:root` 的變數 |

程式分區：`2 工具` → `3 設定` → `4 monday 資料層` → `5 分析引擎` → `6 示範資料` → `7 畫面` → `8 AI 助理` → `9 事件`。
`5 分析引擎` 完全不碰畫面，可以原封不動搬到 Node／GitHub Actions 使用。

## 判斷邏輯的幾個重點

- **到期日**：「預計時程」的結束日，今天以 `Asia/Taipei` 計算；**不採用** monday 的「剩餘天數狀態」標籤（它有過期未更新的情形）。
- **最後活動**：取「建立日、已開始的預計開始日、有效的『最近更新日期』、最近留言」中最晚的。**不使用** monday 的 `updated_at`，因為自動化每天都會改動它。「最近更新日期」若早於建立日或開始日，視為複製範本帶來的舊值而忽略。
- **看板上完全沒有更新紀錄的項目**會標「無紀錄＊」，天數從建立日起算，實際可能有子項目的動靜（本頁沒有讀子項目），請向負責人確認。
- **審核等待天數**：看板沒有「送審時間」，以「完成日期，沒有就用預計結束日」估算，是估計值。看板也無法判斷項目是否已線下審過。
- 驗證過：用真實看板資料跑，進行中 49 項、審核積壓 17 項（最久 200 天）、逾期輕／中／嚴重 8／9／9，與 monday agent 的結果一致。

## 已知限制

- **這是被動頁面**：頁面沒開，就不會主動提醒。能做到的是「開著時每 30 分鐘更新＋瀏覽器通知」。
  要做到不開頁面也推播（Teams／Email），需要定時執行：把 `5 分析引擎` 搬到 GitHub Actions 排程跑，再推到 Teams webhook。這一步尚未做。
- 單頁一次載入所有進行中項目（每 200 筆分頁讀取）；看板很大時載入會稍慢。
- 預審一次只讀單一項目的完整內容（含子項目與最近 20 則留言），不含附件內容本身。
